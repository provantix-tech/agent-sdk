# Changelog

## 0.4.1

- **A first run with a `spoolDir` that does not exist yet no longer fails.** In 0.4.0 (and earlier versions that persisted the handle key), `new AgentEmitter({ spoolDir })` failed with `ENOENT` on `handle-key.bin.tmp` when the directory had not been created: the key was written before the spool created the directory. The directory is now created first. Nothing else changes.

## 0.4.0

Everything since 0.3.0. Nothing is removed or renamed, so an existing emitter keeps working as it is; upgrade with `npm install @provantix/agent-sdk@0.4.0`. Where a feature needs the platform to know it (decision and control evidence, exact-change approvals, cost tags, token kinds, configuration), the platform has accepted all of it already.

- **Configuration: the feature flag variant a step ran under.** `buildAAR({ configuration: [{ flag, variant, provider? }] })` states the feature flags a step ran under and the variant each served, at most ten. A variant is a string, a number or a boolean, kept as text; anything else is refused when you write it. The OpenTelemetry exporter now reads the same from `feature_flag.key`, `feature_flag.result.variant` and `feature_flag.provider.name` on a span, or on its `feature_flag.evaluation` events, with the same code the hosted intake uses, so a step is described the same way however it arrives. Provantix shows the variant on the run, keeps evaluation windows under different configurations apart, and checks, after a control system reports a rollback, that the same cohort is on the expected variant. Give every step of one run the same `correlation.traceId`: expected steps and recovery checks group a run by it.
- **The OpenTelemetry exporter no longer imports files outside the package.** In 0.3.0, `src/otel.mjs` imported modules that exist only in the Provantix repository (`../../../ledger/packages/aar-schema/src/...`), so an installed copy could not load the OTel mapping, which `index.mjs` re-exports. The modules it needs (`delegation`, `tool-payload`, `usage`, `tags`, `configuration`) are now vendored in `src/vendor/`, and a test fails if any file the package ships imports outside `src/`.

- **The source's own cost, and framework metadata.** `buildAAR({ model })` accepts `reportedCostUsd` (and `reportedCostBy`): what the source says the call cost, in US dollars. Provantix keeps it as reported by that source beside its own estimate and never in its place. The OpenTelemetry mapping reads it from `provantix.usage.cost_usd` only; other cost attributes do not state a unit and are not read. A standard tag name set as run metadata (`langsmith.metadata.department`, `traceloop.association.properties.department`, or a `metadata` JSON attribute) is read as a tag. Needs a Provantix that keeps source-reported cost; an older one ignores the field.

- **Cost tags.** `buildAAR({ tags })` takes the tags a source states about a call: department, cost center, product, project, environment, or any other name (`{ department: 'sales', region: 'emea' }`). They are kept in the record as stated. The OpenTelemetry mapping reads them from the span attributes `provantix.cost.department`, `.cost_center`, `.product`, `.project`, `.environment`, any `provantix.tag.<key>`, and `deployment.environment.name` for the environment, the same as the hosted intake. A tag a source states wins over one an admin sets on the agent. Left out, a call is unallocated for that dimension, never guessed. Needs a Provantix that resolves cost tags; an older one keeps them in the record and ignores them.

- **Token kinds on a model call.** `buildAAR({ model })` accepts `tokensCacheRead`, `tokensCacheWrite`, `tokensReasoning`, `serviceTier` (`standard`, `batch`, `priority` or `flex`) and `usageBasis`, kept in the record only when given. `tokensIn` is all input tokens including the cached part, and `tokensOut` all output including reasoning. The OpenTelemetry mapping reads the cache, reasoning and tier attributes (`gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens`, `gen_ai.usage.reasoning.output_tokens` and the names other instrumentations use) and adds up a provider that reports its input without the cache (Anthropic), so the figures mean the same for every provider. Left out, they read as not recorded, never zero. Needs a Provantix that prices each token kind; an older one stores them and ignores them.

- **Exact-change approvals.** An approval can now say the exact production change it was given for: `authorization.binding` accepts `environment`, `resource`, `operation`, `change_digest`, `risk_ref` and `break_glass` (an emergency route, which is recorded as one and never shown as an ordinary approval). The action says what it changed with `ext: { mutation: buildMutation({ environment, resource, change }) }`, and `changeDigest(change)` computes the same digest on the approval side. `buildMutation` and `changeDigest` are new exports. The change itself is never kept, only its digest. An approval that states none of the new fields is checked exactly as before. The vendored `collector.mjs` is synced from the engine.
- **Instruction and model references on a decision.** `buildDecisionAAR` accepts `intentRef` (the instruction or ticket the decision answers: `ref`, optional `sha256` and `kind`) and `modelRef` (the model invocation behind it: `modelId`, optional `provider`, `modelVersion`, `invocationRef`). References only: the instruction and the prompt are not kept, and a credential or an unnamed field is refused. Left out, they read as not recorded.
- **Control decision evidence.** `buildControlDecisionAAR({ ... })` records what an enforcement tool decided about an action an agent proposed: the verdict (`allow`, `ask`, `deny` or `steer`), the enforcer, the policy and its version, a short reason, what was proposed, and an action id when there is one. `controlRef(control)` gives the pointer an action's own record can carry (`ext: { control_ref }`) so Provantix joins them exactly. Also exported: `CONTROL_VERSION`, `CONTROL_VERDICTS` and `CONTROL_LIMITS`. Credentials and any field the contract does not name (a raw prompt, a tool's full arguments) are refused. Needs a Provantix that compares control decisions (the format is unchanged: it travels in the record's sealed `ext`).
- **Decision evidence.** `buildDecisionAAR({ ... })` records why an agent chose an action, before it acts: a hypothesis with the evidence it cites, the candidate actions, the one selected, what was rejected and why, and a risk reference. `decisionRef(decision)` gives the pointer to put on the action's own record (`ext: { decision_ref }`), so the two records cite each other. Also exported: `DECISION_VERSION`, `DECISION_SOURCES` and `DECISION_LIMITS`. Text is kept short, as summaries and references; anything that looks like a credential, and any field the contract does not name (a raw prompt, a reasoning trace), is refused. What the agent did not say reads as not recorded. Needs a Provantix that shows decision evidence (the format is unchanged: it travels in the record's sealed `ext`).
- **Approval binding.** An approval can say what it was given for: `authorization.binding = { target_system, target_entity_id, action_type, max_amount_minor, currency, expires_at, policy_version }`, or the matching `provantix.approval.*` span attributes. Provantix then shows "approval present" and "authority verified" separately. Every field is optional. Records without a binding keep working and read as "present, binding not recorded". Requires a Provantix with approval binding; an older one stores the binding with the record and ignores it.

## 0.3.0

- **Spool size.** `new AgentEmitter({ spoolMaxBytes })` sets how much the on-disk queue may hold while ingest is unreachable. The default stays 2 GiB; `null` removes the limit, for a customer-run Provantix with no volume restrictions (the disk is then the only limit).
- **Location.** `new AgentEmitter({ location })` says where the emitter runs and what it acts on, as short codes: `{ runtime: { provider, region, zone, country }, target: { region, country } }`. With no setting it reads the cloud region it runs in (`AWS_REGION`, `GOOGLE_CLOUD_REGION`, `FLY_REGION`, `VERCEL_REGION`) when one is set. `buildAAR({ location })` overrides it for one action. The location is part of the sealed record, so the seal and the batch signature cover it, and Provantix shows it as declared. Nothing finer than a country is kept: a city, an address or free text is dropped before sealing, and the platform refuses a record that carries one.
- The vendored `collector.mjs` is synced from the engine (it carries `location` into the record fields).
- Requires a Provantix that accepts location, which every current platform does. A record without a location is unchanged.

## 0.2.0

- **Sealed batches.** The emitter signs the hash of every record in each batch (the batch seal) and adds it to the envelope, which moves to version 1.1. On by default; `seal: false` restores the unsealed 1.0 batch. An auditor can check the seal with the emitter's public key, without trusting Provantix, and it still verifies after a person's data is erased.
- Batches queued by an older version are sealed when 0.2.0 sends them (same records, same batch number, same creation time), so an emitter paused at the deadline can be upgraded without losing what it queued.
- Also in this release, from work done since 0.1.1 that was not yet published: approvals mapped into the record's `authorization` block (`provantix.approval.*` attributes), the delegation chain rebuilt from span parentage, tool arguments, results, data classes and the external recipient on records, an OpenTelemetry SpanExporter for one-line instrumentation, the stable target-system contract for run ids, and runnable examples. If you run 0.1.1 in production, check these against your setup before upgrading.
- The vendored `batch.mjs` and `collector.mjs` are synced from the engine. A test fails if they drift.
- Requires a Provantix that accepts seals. Sealed batches are accepted by every current platform; unsealed batches will be refused after the notice period Provantix sends.
